Install the packed CLI on two Linux tailnet machines, copy these units into `/etc/systemd/system/`, then run `systemd-analyze verify encrypted-share-send.service encrypted-share-send.timer encrypted-share-receive.service` before enabling the sender timer and receiver service.

The receiver unit requires [PR #4](https://github.com/nithin-murali-arch/encrypted-share/pull/4), which adds `serve --host`. Released 3.0.1 does not support that option. Wait for a release containing that change or install a reviewed package built from that branch. Do not enable this receiver unit with 3.0.1.

Create an `encrypted-share` system user on each machine. Install Node.js 20 or later and the CLI at `/usr/local/bin/encrypted-share`, or edit `ExecStart` to use your installed path. Give the sender read access to `/var/log/field-device`, including traversal permissions. Give both machines a reachable tailnet address and permit TCP port 3000 in their tailnet policy and firewall.

On the sender, create `/etc/encrypted-share/send.json` with `{"server":"100.100.10.20:3000","key":"replace-with-a-long-shared-password"}`. On the receiver, create `/etc/encrypted-share/receive.json` with `{"key":"replace-with-a-long-shared-password"}` and `/etc/encrypted-share/receiver.env` with `ES_HOST=100.100.10.20`. Replace the address with the receiver's tailnet IP. Make `/etc/encrypted-share` root-owned and the config files readable only by root and the service user's group. Use separate receiver directories and ports for separate devices.

The receiver uses `--overwrite` because each scheduled send includes every file. A changed log replaces its previous copy. This is a snapshot of one device's log directory, not incremental sync or an archive. Rotate or copy actively written logs into a stable directory before sending, then change the sender's source path to that directory.

Run `sudo systemctl daemon-reload`, `sudo systemctl enable --now encrypted-share-receive.service` on the receiver, and `sudo systemctl enable --now encrypted-share-send.timer` on the sender. Run `sudo systemctl start encrypted-share-send.service` for the first send. Inspect `journalctl -u encrypted-share-send.service` and `journalctl -u encrypted-share-receive.service` for transfer results.

Run `sh verify-containers.sh /absolute/path/nithin93-encrypted-share-3.x.y.tgz` with Docker and `node:22-alpine` available locally to prove a real transfer between two containers. Their Docker network is internal and both installs use an empty cache with `--offline`. The receiver explicitly passes `--host 0.0.0.0`, so the check also exercises PR #4's CLI option. It checks transfer separately from systemd scheduling, Linux permissions, and live Tailscale reachability. Binding a specific tailnet address still requires that address on the deployed receiver.
